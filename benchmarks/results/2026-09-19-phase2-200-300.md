# Phase 2 200/300-player results

Local shared-host diagnostic on Windows 11, Intel i3-12100F (8 logical
processors), JDK 25, loopback server and bots, no plugins, pooled Netty
allocator, locator bar enabled, waypoint collections enabled, and the prepared
spread fixture. The final source includes waypoint patches 0044, 0045, and
0046. No mob caps, spawn rules, or survival mechanics were changed.

## 200 players — pass

Run `smoke-2026-09-18T16-40-29-382Z-e72f9e74` used view distance 8 and
simulation distance 6.

| Metric | Result |
|---|---:|
| Bots | 200; all spawned; 0 unexpected disconnects |
| Native minimum TPS | 20 |
| Worst rolling 60-second MSPT | 37.8 ms |
| Maximum tick | 66.5 ms |
| Driver result | PASS |

The run completed the mixed workload: movement, jumps, attacks, block breaks,
block placement, inventory cycles, container opens, chat, commands, and ping
round trips.

## 300 players — current limit

At view distance 8 / simulation distance 6, run
`smoke-2026-09-18T16-10-29-490Z-35a36eab` spawned all 300 bots but one bot was
kicked for flying after a warmup tick delay of 1,022 ms. The stage stopped
before a valid active window.

Repeating at view distance 6 / simulation distance 4 in
`smoke-2026-09-18T16-15-33-848Z-90b2d7ab` reduced the peak warmup delay to
752 ms, but the same workload still produced one flying kick before telemetry
could pass the workload gate.

To measure the steady state without that kick hiding the result, the
test-only fixture set `allow-flight=true`; this setting is not a production
recommendation. Run `smoke-2026-09-18T16-47-09-042Z-1a60735a` reached only
6.7–6.8 TPS and 146.9–149.9 ms MSPT at 300 active mixed bots. The JFR sample
was spread across `NaturalSpawner`, `HashMap`, `LongOpenHashSet`, entity
tracking, and player lookup work.

A no-listener `PreCreatureSpawnEvent` fast path was measured separately in
`smoke-2026-09-18T16-57-49-379Z-f96e4f1f`; it reached about 6.2 TPS / 160 ms
MSPT and was reverted. The final tree contains no part of that experiment.

The evidence supports the 200-player gate on this CPU. Three hundred active
players remains beyond the current survival-safe headroom; changing spawn
rules, tracking ranges, or simulation distance would trade gameplay behavior
for a benchmark number and was not kept.
