# Phase 3 high-player optimization results

Date: 2026-09-19
Host: Windows 11, Intel i3-12100F (8 logical processors), JDK 25
Scope: local loopback, no plugins, pooled Netty allocator, locator bar enabled,
waypoint collections enabled, pregenerated arena fixture.

## Changes measured

* **0048** reuses Moonrise's `NearbyPlayers.SPAWN_RANGE` index for natural-spawn
  nearest-player lookup and keeps the exact upstream fallback when the index has
  no eligible player.
* **0049** staggers locator connection updates above 200 players. Connections
  remain present; only live position/azimuth refreshes are spread across ticks.
  At 450 players this can delay a marker refresh by up to roughly 4.5 seconds.
* `spawning.mob-spawn-range` is now configurable from 1 to 8 chunks. The value
  4 run below is an opt-in survival tuning result, not the default.

## Retained runs

| Change / run | Players | View / sim | Result | Worst mean MSPT | p95 | p99 | Min TPS |
|---|---:|---:|---|---:|---:|---:|---:|
| 0048 matched candidate | 200 | 8 / 6 | PASS | 37.10 | 41.92 | 47.86 | 20.00 |
| 0049 staggered cadence | 300 | 8 / 6 | gate fail | 41.11 | 49.77 | 60.00 | 20.00 |
| 0049 staggered cadence | 450 | 6 / 4 | gate fail | 46.47 | 54.94 | 59.65 | 19.96 |
| 0049 + spawn range 4 | 450 | 6 / 4 | gate fail | 47.35 | 56.27 | 64.66 | 19.83 |

The 450 mixed workload spawned all 450 clients, completed its actions, and had
zero unexpected disconnects. The strict gate failed because mean MSPT exceeded
40 ms and the rolling p95/p99 exceeded 50 ms. Lowering natural spawn range to 4
did not improve this fixture; the default 0049 run remains the best retained
450 result.

## Remaining hotspot

JFR for the best 450 run placed `ChunkMap$TrackedEntity.updatePlayer` first,
followed by Moonrise nearby-player map lookup, `seenBy` membership, chunk entity
collection, and `NaturalSpawner.getNearestPlayerForSpawning`. Locator update
methods were no longer in the retained top list after 0049, so further locator
changes are unlikely to close the remaining 6–7 ms mean gap by themselves.

The result supports keeping 0048 and 0049 while treating 450/20-TPS as
unverified. The next code candidate should reduce entity viewer maintenance or
prove a safe tracking cadence; it must be benchmarked against the same 200/300/
450 fixture before being retained.

## Rejected follow-up

A temporary 0050 candidate staggered entity visibility membership checks across
three ticks above 200 players. The 450 run stayed valid but measured 46.53 ms
mean, 57.19 ms p95, and 67.35 ms p99 versus 0049's 46.47 / 54.94 / 59.65.
It was removed from the source and is not part of the retained optimization.
